# 52 — Testing Strategy

1. **Unit (Rust):** every module has tests. Timer wheel property tests (proptest): random insert/cancel/advance sequences against a BTreeMap model.
2. **Model checking (loom):** task state machine, inbox/injector/steal, Notify, Semaphore grant-vs-cancel, mpsc close races, scope cancel vs spawn. The models are in `crates/porto-core` (`loom_tests` modules next to what they check; one in `porto-io` for the registration's close gate) and all run under `RUSTFLAGS="--cfg loom" cargo test -p porto-core --release` (a plain `cfg`, no cargo feature). They cover: the task state machine, join and scope-exit waiters, the lane's parking protocol against the injector; the wait queue's grant-vs-cancel and the `Lock`/`Mutex`, `Semaphore`, `RwLock`, `Condition`, `Barrier`, `Event`, `Notify` built on it; the bounded and unbounded channel (close races, the send/receive wake-up handshake, a closed handle passing on the wake it holds); `oneshot`, `watch` and `broadcast` (cancelled receives, closes, exact lag counts); and the scope tree (cancel vs spawn, nested scopes, shields, waiters, the walk cache, deadline fire vs close/re-arm/cancel, adopt). A model with three threads, or over the channel's spinning queue, declares the largest preemption bound it can finish under; the others are exhaustive. `LOOM_MAX_PREEMPTIONS` lowers every model to that bound and never raises a capped one. CI runs them as in `51` §2.
3. **Python semantic tests:** one file per spec section with the normative rules as test names, e.g. `test_C1_level_triggered`, `test_C4_child_failure_cancels_siblings`, `test_T3_trap_cancel_safe_read`. Every MUST in this spec maps to at least one test (traceability matrix generated by `scripts/rule_matrix.py`, which greps the rule IDs a spec declares, as a bold bullet or a table row, against the test names; `--check N` fails when a rule of spec `N` has no test, and CI runs it for spec 15, whose suite is `tests/python/porto/test_15_scopes.py`, and for spec 16, whose rules are `SY1`–`SY39` (`16` §4) and whose suite is `tests/python/porto/test_16_sync.py`).
4. **Trio-derived tests:** port the relevant subset of Trio's test suite for cancel scopes and nurseries (MIT/Apache license compatible), adapted to the Porto API.
5. **Deterministic stress:** concurrency scenarios (chat server, connection pool, pipeline) under `porto.testing.explore` with 1000 seeds.
6. **Fuzzing (cargo-fuzz):** JSON lexer+validator, router normalization, multipart parser, HTTP request head (via hyper), and the WebSocket frame codec.
7. **Compat suites:** §51.
8. **Free-threaded race tests:** run the Python suite with `lanes=8` on 3.14t under a TSAN-built CPython nightly.
9. **Leak tests:** run each test 100× under `tracemalloc` + RSS sampling + FD counting. The growth limit is 0 objects after warmup.
10. **Douro end-to-end:** real sockets, TLS, h2 via `httpx`/`h2load`, plus graceful-shutdown tests that send SIGTERM mid-load and assert that zero requests are lost (completed or properly refused).
